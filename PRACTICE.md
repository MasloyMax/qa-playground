# Задания для самостоятельных тестов

В заготовке три примера. Остальные сценарии напиши сам, по одному за раз. Правила магазина — в [API.md](API.md).

## 1. Вход

- Успешный вход: окно закрывается, появляется кнопка выхода.
- Неправильный пароль: видна ошибка, пользователь остаётся неавторизованным.
- Заблокированный аккаунт.
- Пустые поля.
- Выход: доступна кнопка входа, закрытые запросы возвращают 401.
- Обновление страницы после входа сохраняет сессию.

Сначала напиши отдельные тесты, затем объедини похожие случаи в параметризованный тест JUnit.

## 2. Каталог

- Поиск по части названия, включая другой регистр.
- Неизвестное название: пустой результат.
- Каждая категория возвращает только свои товары.
- Сортировка цены в обе стороны.
- Фильтр наличия исключает камеру.
- Переход на вторую страницу и обратно.
- Смена фильтра на второй странице возвращает на первую.
- Сброс возвращает исходные фильтры.
- Подробная карточка показывает нужный товар.
- Недоступный товар нельзя добавить через UI и API.

## 3. Корзина и расчёты

- Добавление одного товара, затем повторное добавление.
- Несколько разных товаров.
- Увеличение и уменьшение количества.
- Максимальный остаток и превышение остатка через API.
- Отрицательное, дробное, строковое и нулевое количество через API.
- Удаление последней позиции: пустое состояние, нулевая сумма.
- Правильный и неверный промокод, пробелы и другой регистр.
- Повторный промокод не удваивает скидку.
- Удаление промокода восстанавливает сумму.
- Доставка до и после порога бесплатной доставки.

Ожидаемую сумму считай в тесте из известных условий. Не копируй её из ответа сервера в ожидаемый результат.

## 4. Оформление

- Покупка одного и нескольких товаров.
- Пустые поля.
- Границы длины имени: 1, 2, 80, 81 символ.
- Неверные почта и телефон.
- Ошибка формы сохраняет корзину.
- Успех очищает корзину и добавляет заказ в историю.
- В заказе совпадают товары, количество, скидка и доставка.
- Повтор запроса с тем же `Idempotency-Key` возвращает прежний заказ.
- Тот же ключ с другим получателем даёт 409.
- Новая сессия не получает доступ к заказу предыдущей.

## 5. Организация Java-кода

- Добавь `CartPage`, `CheckoutPage`, `OrdersPage` и их локаторы.
- Создай `record Customer(...)` для данных доставки.
- Вынеси создание подходящего покупателя в отдельный метод.
- Создай Java-модели ответов API и извлеки их через `.as(...)`.
- Раздели UI и API тегами JUnit.
- Добавь понятные `@DisplayName`.
- Проверь, что каждый тест проходит отдельно и после других тестов.
- Открой HTML-отчёт Gradle и скриншот намеренно упавшей проверки.
- Запусти тесты в видимом и фоновом режимах.

## 6. Сценарий с UI и API

Войди через API, сохрани cookie сессии и передай её браузеру на домене магазина. Подготовь корзину через API, оформление выполни через UI. После этого проверь заказ запросом API.

Используй одну сессию: отдельный вход через UI создаст другую пустую корзину.

## Как работать с ошибкой

1. Прочитай сообщение и ожидаемый результат.
2. Посмотри скриншот, HTML или тело ответа.
3. Повтори действие вручную.
4. Определи, ошибочен тест или приложение.
5. Исправь причину и повтори нужную проверку.

Не добавляй `Thread.sleep()` для исправления случайных падений. Используй ожидание конкретного состояния через Selenide.
