# API магазина

Базовый адрес: `http://127.0.0.1:3000/api`.

Тело запроса передавай как JSON с `Content-Type: application/json`. Максимальный размер — 16 КиБ. Пример ошибки:

~~~json
{
  "code": "VALIDATION_ERROR",
  "message": "Проверьте данные доставки.",
  "fields": {"phone": "Телефон: от 10 до 15 цифр, можно начать с +."}
}
~~~

## Вход и данные сессии

| Метод и путь | Тело / результат |
|---|---|
| `GET /health` | `200`: `{"status":"UP","application":"practice-market"}` |
| `POST /auth/login` | `{"email":"demo@practice.dev","password":"practice123"}` → `200` и cookie `practice_session` |
| `GET /me` | `200`: `id`, `name`, `email`; без сессии — `401` |
| `POST /auth/logout` | `204` без тела; сессия становится недействительной |

Неправильные данные входа — `401 INVALID_CREDENTIALS`. Заблокированный пользователь с правильным паролем — `403 USER_LOCKED`.

Сохраняй cookie входа и передавай её дальше. `ShopApi` делает это через `CookieFilter`, Postman — через cookie jar. Cookie имеет `HttpOnly`, поэтому из JavaScript её прочитать нельзя.

Корзина и заказы принадлежат конкретной сессии. У каждой новой сессии они пустые. Данные хранятся в памяти, срок сессии — 2 часа с момента входа. Перезапуск сервера удаляет все сессии.

## Каталог

`GET /products` доступен без входа.

| Параметр | По умолчанию | Допустимые значения |
|---|---|---|
| `search` | Пустая строка | Подстрока названия; регистр и пробелы по краям не учитываются |
| `category` | Все категории | `audio`, `workspace`, `home`, `travel` |
| `sort` | `name` | `name`, `price_asc`, `price_desc` |
| `inStock` | `false` | `true` исключает товары с нулевым остатком |
| `page` | `1` | Целое число 1–10000 |
| `size` | `6` | Целое число 1–100 |

Пример: `GET /products?category=audio&sort=price_asc&page=1&size=6`.

Ответ: `{"items":[...],"total":2,"page":1,"size":6}`. `total` — число товаров после фильтрации, до пагинации. За последней страницей `items` пустой. Некорректный параметр из таблицы даёт `400`.

`GET /products/{id}` возвращает товар (`200`) или `404 PRODUCT_NOT_FOUND`.

|---|---|---|---:|---:|
| 1 | Наушники Wave | audio | 4900 | 8 |
| 2 | Клавиатура Type | workspace | 6200 | 5 |
| 3 | Лампа Halo | home | 2800 | 12 |
| 4 | Колонка Pebble | audio | 3500 | 6 |

Поля товара: `id`, `name`, `category`, `categoryName`, `price`, `stock`, `icon`, `color`, `description`.

## Корзина

Все методы требуют сессию. Без неё — `401 UNAUTHORIZED`.

| Метод и путь | Тело | Поведение |
|---|---|---|
| `GET /cart` | — | Текущая корзина |
| `POST /cart/items` | `{"productId":1,"quantity":1}` | Добавляет количество к уже имеющемуся |
| `PATCH /cart/items/{id}` | `{"quantity":2}` | Заменяет количество |
| `DELETE /cart/items/{id}` | — | Удаляет позицию |
| `DELETE /cart` | — | Очищает корзину и промокод |
| `POST /cart/coupon` | `{"code":"PRACTICE10"}` | Скидка 10% |
| `DELETE /cart/coupon` | — | Удаляет промокод |

Успешные операции возвращают `200` с текущей корзиной:

~~~json
{
  "items": [
    {
      "product": {"id": 1, "name": "Наушники Wave", "price": 4900, "stock": 8},
      "quantity": 1,
      "lineTotal": 4900
    }
  ],
  "count": 1,
  "subtotal": 4900,
  "discount": 490,
  "shipping": 300,
  "total": 4710,
  "coupon": "PRACTICE10",
  "currency": "RUB"
}
~~~

Объект `product` в примере сокращён; сервер возвращает все его поля.

Правила:

- `productId` — JSON-число, целое. Не строка.
- `quantity` — целое число от 1 до 99 и не больше остатка. Ноль не удаляет позицию: используй `DELETE`.
- Неверное количество — `400 INVALID_QUANTITY`. Превышение остатка — `409 OUT_OF_STOCK`; корзина не меняется.
- Несуществующий товар — `404 PRODUCT_NOT_FOUND`. Изменение или удаление отсутствующей позиции — `404 CART_ITEM_NOT_FOUND`.
- Неверный промокод — `400 INVALID_COUPON`; правильный код для пустой корзины — `409 EMPTY_CART`.
- Регистр и пробелы по краям промокода не учитываются. Повторное применение не складывает скидки.
- Все цены и суммы — целое число рублей.
- `subtotal` — сумма товаров. `discount` — 10% от неё с округлением до целого рубля.
- Доставка — 300 ₽; если `subtotal - discount >= 5000`, доставка бесплатная.
- `total = subtotal - discount + shipping`. Для пустой корзины доставка и итог равны нулю.

## Оформление и история

`POST /orders`:

~~~json
{
  "name": "Анна Иванова",
  "email": "anna@example.com",
  "phone": "+79991234567",
  "address": "Москва, улица Лесная, дом 10"
}
~~~

| Поле | Правило после удаления пробелов по краям |
|---|---|
| `name` | От 2 до 80 символов |
| `email` | Непустые части до и после `@`, точка в домене, без пробелов; максимум 120 символов |
| `phone` | От 10 до 15 цифр, допустим `+` в начале; без пробелов и скобок |
| `address` | От 10 до 200 символов |

Ошибки данных — `400 VALIDATION_ERROR` с полями в `fields`. Корзина при ошибке сохраняется. Пустая корзина с корректными данными — `409 EMPTY_CART`.

Успех — `201`. Ответ содержит `id`, `status: "CREATED"`, `createdAt`, `customer` и снимок корзины со всеми суммами. После создания корзина и промокод очищаются. Позднейшее изменение корзины не меняет заказ.

- `GET /orders` → `200`, `{"items":[...]}`; новые заказы первыми.
- `GET /orders/{id}` → `200` или `404 ORDER_NOT_FOUND`. Чужой заказ также даёт `404`.

Для безопасного повтора передай заголовок `Idempotency-Key`, например `order-001`. Допустимо 1–100 латинских букв, цифр, дефисов и символов `_`.

- Первый запрос с ключом: `201`, новый заказ.
- Повтор с тем же ключом и теми же данными получателя: `200`, тот же заказ, даже при пустой корзине.
- Тот же ключ с другими данными: `409 KEY_CONFLICT`.
- Для новой покупки нужен новый ключ.
- Ключи действуют только внутри текущей сессии.
- Без ключа защита от повторного создания не предоставляется.

Неизвестный маршрут — `404`. Неподдерживаемый метод известного закрытого маршрута при действующей сессии — `405`.

## Локаторы интерфейса

| Элемент | `data-testid` |
|---|---|
| Открыть вход | `login-open` |
| Почта / пароль / отправка | `login-email`, `login-password`, `login-submit` |
| Ошибка входа / выход | `login-error`, `logout` |
| Поиск / категория / сортировка | `search`, `category`, `sort` |
| Наличие / сброс | `in-stock`, `reset-filters` |
| Каталог / карточка / название / цена | `product-grid`, `product-card`, `product-name`, `product-price` |
| Пагинация | `prev-page`, `next-page`, `page-number` |
| Добавить товар | `add-to-cart` |
| Добавить из подробной карточки | `detail-add-to-cart` |
| Корзина / счётчик | `cart-link`, `cart-count` |
| Позиция / количество / удалить | `cart-item`, `quantity`, `remove-item` |
| Увеличить / уменьшить | `increase`, `decrease` |
| Промокод / применить / убрать / ошибка | `coupon`, `apply-coupon`, `remove-coupon`, `coupon-error` |
| Товары / скидка / доставка / итог | `subtotal`, `discount`, `shipping`, `total` |
| Оформить | `checkout-link` |
| Получатель | `checkout-name`, `checkout-email`, `checkout-phone`, `checkout-address` |
| Подтвердить / ошибка | `place-order`, `checkout-error` |
| Успех / номер | `order-success`, `order-id` |
| История / заказ | `orders-link`, `order-card` |

Карточки и позиции корзины имеют `data-product-id`. Суммы повторяются в корзине и оформлении: ищи их внутри `#cart-view` или `#checkout-view`.

У `product-grid` есть `aria-busy`: `true` при загрузке, `false` после завершения. Проверяй ожидаемый результат фильтрации с ожиданием Selenide: одной проверки `aria-busy=false` до начала запроса недостаточно.
