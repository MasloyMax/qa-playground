# Инструкции для работы с проектом

## Назначение и структура

Это учебный проект «Практика Маркет» для освоения автоматизации тестирования на Java.

- `autotests/` — основной проект для упражнений: Java 17, JUnit Jupiter, Selenide, REST Assured, Jackson и Gradle Wrapper. Точные версии находятся в `autotests/build.gradle`.
- `autotests/src/test/java/practice/config/` — загрузка конфигурации.
- `autotests/src/test/java/practice/ui/` — базовый UI-класс, локаторы, Page Object и тесты.
- `autotests/src/test/java/practice/api/` — API-клиент и тесты.
- `autotests/src/test/resources/test.properties` — настройки тестов по умолчанию.
- `shop-app/` — приложение на Node.js с HTTP API и интерфейсом на обычных HTML, CSS и JavaScript. Внешних npm-зависимостей нет.
- `shop-app/test/app.test.js` — служебные тесты самого приложения через `node:test`.
- `README.md` — запуск, структура и настройки; `API.md` — контракт и бизнес-правила; `PRACTICE.md` — учебные задания.

## Учебный формат

- Общайся с пользователем на русском языке и объясняй Java простыми словами, связывая объяснение с его кодом.
- Различай просьбу объяснить код и просьбу изменить проект. Для объяснения обычно достаточно конкретного примера.
- При исправлениях сохраняй самостоятельные правки пользователя и ограничивай изменения текущей задачей. Пользователь может редактировать файлы одновременно с агентом.
- Не выполняй остальные задания из `PRACTICE.md` автоматически и не перестраивай проект ради одного упражнения.

## Запуск и команды

Команды ниже выполняются из корня проекта в PowerShell. Требования и настройка JDK описаны в `README.md`: Node.js 22+, JDK 17–25, Chrome для UI-тестов.

Запуск магазина в отдельном терминале:

```powershell
node .\shop-app\server.js
```

Адрес по умолчанию — `http://127.0.0.1:3000`; проверка готовности — `GET /api/health`. Java-тесты используют внешний сервер и не запускают его сами. Перед запуском нового экземпляра проверь, не работает ли приложение на нужном порту.

| Проверка | Команда |
| --- | --- |
| Все Java-тесты | `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run-tests.ps1` |
| Только UI | `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run-tests.ps1 -Suite ui` |
| Только API | `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run-tests.ps1 -Suite api` |
| Один UI-класс | `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run-tests.ps1 -Suite ui -Test '*LoginTest'` |
| Тесты самого магазина | `node --test .\shop-app\test\app.test.js` |

- `run-tests.ps1` использует `JAVA_HOME` или доступный JDK курса, размещает Gradle-кэш в `.runtime/gradle` и восстанавливает переменные окружения после работы.
- Запускай `run-tests.ps1` отдельным процессом PowerShell, как в примерах: внутри скрипта есть `exit`.
- Для видимого браузера добавь `-Visible`, для другого адреса — `-BaseUrl http://127.0.0.1:3001`.
- Если ChromeDriver уже скачан, передай его реальный путь через `-DriverPath`. Не записывай абсолютные пути конкретной машины в исходный код.
- При настроенном JDK из каталога `autotests/` доступны `./gradlew.bat compileTestJava`, `./gradlew.bat uiTest`, `./gradlew.bat apiTest` и `./gradlew.bat test`. На Linux/macOS используй `sh ./gradlew`.
- Тесты `node:test` поднимают отдельный сервер на свободном порту; предварительный запуск магазина им не нужен.

## Правила Java-тестов

- Сохраняй совместимость с Java 17 и кодировку UTF-8. Используй существующие пакеты `practice.*`, стиль соседних файлов и понятные русские `@DisplayName`.
- UI-тесты наследуются от `UiTestBase`: он создаёт отдельный `SelenideDriver` на каждый тест и закрывает его после теста. Тег `ui` наследуется от базового класса.
- Локаторы размещай в `ui/locators`, действия и проверки страниц — в `ui/pages`, сценарии — в `ui/tests`. Используй существующие `data-testid`.
- Метод Page Object должен возвращать текущую страницу через `this` либо объект страницы, на которую переходит сценарий. После изменения возвращаемого типа проверь все цепочки вызовов.
- Подготовка в `@BeforeEach` должна подходить всем тестам класса. Например, класс с успешным и неуспешным входом не должен авторизовываться перед каждым тестом.
- Для API создавай отдельный `ShopApi` в каждом тесте: его `CookieFilter` хранит cookie сценария. API-классы помечай `@Tag("api")`.
- Ожидаемые значения рассчитывай из известных условий. Не подставляй фактический результат ответа сервера в ожидаемый.
- Для ожиданий используй условия Selenide. Не исправляй нестабильные тесты добавлением `Thread.sleep()` или удалением проверок.

## Конфигурация и данные

- `TestConfig` выбирает значения в порядке: JVM property → переменная окружения → `test.properties`.
- Gradle передаёт параметры `-PbaseUrl`, `-Pheadless`, `-Pbrowser`, `-Ptimeout` в JVM тестов. Скрипт `run-tests.ps1` всегда задаёт адрес через свой параметр `-BaseUrl`.
- Во всех частях одного сценария используй один хост: cookie для `localhost` и `127.0.0.1` не взаимозаменяемы.
- Успешный вход создаёт новую сессию с пустыми корзиной и историей, даже для одного логина. Данные сессий хранятся в памяти; перезапуск сервера их удаляет.
- В смешанном UI/API-сценарии передавай cookie одной сессии между API-клиентом и браузером. Повторный вход создаст другую сессию.
- Тестовые аккаунты и бизнес-правила сверяй с `README.md` и `API.md`. При изменении поведения магазина обновляй соответствующую документацию и служебные тесты.

## Проверка изменений

- Выбирай проверки по изменению: компиляция и затронутые Java-тесты для Java-кода; `node:test` для логики магазина; UI-сценарии для изменений интерфейса. Для документации достаточно сверить пути и команды с исходниками.
- При падении сначала прочитай исключение и собери доступные артефакты. Отличай ошибки компиляции, ошибки проверок и проблемы окружения: JDK, сервер, драйвер или падение браузера.
- Отчёты Gradle находятся в `autotests/build/reports/tests/{test,uiTest,apiTest}/index.html`, скриншоты и HTML Selenide — в `autotests/build/selenide/`.
- В результате работы кратко укажи, что изменено, что проверено и какие проверки не удалось завершить.
- `.runtime/`, `autotests/build/`, `.gradle/`, `node_modules/` и `.idea/` содержат локальные или сгенерированные файлы; не используй их как место для исходного кода.
